# install.sh + canonical-as-source restructure

Implementation plan to convert `~/.claude/` from a git clone of `paultyng/skill-issue` into a plain directory populated by an `install.sh` script that runs from the canonical clone at `~/src/github.com/paultyng/skill-issue/`. Approach A (no `--delete`, manifest-based optional `--prune`): user-local skills/rules/scripts are always preserved. Statusline scripts move to `scripts/`; `terseness-check.sh` is removed from canonical (user keeps a personal copy at `~/.claude/scripts/terseness-check.sh`); `settings.json` becomes `settings.merge.json` and is jq-merged into `~/.claude/settings.json` on every install.

## Branch policy

- Branch: 2026-04-30-1708-claude-user-settings-skill-issue
- Base: origin/main

(The Ideate per-idea branch — reuses the current worktree branch.)

## Goal

Make the canonical clone the single source of truth for `skills/`, `rules/`, `scripts/`, `CLAUDE.md`, and a curated set of `settings.json` keys. `~/.claude/` becomes a managed install target — no `.git`, no "this file is dirty per CLAUDE.md" gymnastics. Edits flow canonical → `~/.claude/` via `./install.sh` (or `task install`). User-local skills/rules/scripts are preserved across installs.

## Definition of Done

- Canonical (this repo) has:
  - `scripts/statusline.sh` and `scripts/statusline.ps1` (moved from repo root)
  - No `scripts/terseness-check.sh` (removed from canonical; user retains personal copy outside)
  - `settings.merge.json` (renamed from `settings.json`) with `statusLine.command = "~/.claude/scripts/statusline.sh"`
  - `install.sh` at repo root, executable, additive-by-default, with `--dry-run` / `--migrate` / `--prune` modes
  - `Taskfile.yaml` with `task install`, `task install:dry`, `task install:migrate`, `task install:prune` targets
  - `README.md` section documenting the install workflow
  - Updated global `CLAUDE.md` (top-level in canonical) reflecting the new workflow
- `install.sh` is additive (no `rsync --delete`); writes a manifest to `~/.claude/.skill-issue-manifest.json` listing every file it installs; `--prune` uses the manifest to remove only files this script previously installed and canonical no longer ships
- `install.sh --migrate` is idempotent and removes `~/.claude/.git` + `~/.claude/.gitignore` on first run only
- Smoke test in a fake `$HOME/.claude` (e.g. `/tmp/test-claude-install`) shows: SYNC_DIRS populated, `CLAUDE.md` synced, manifest written, `settings.merge.json` shared keys applied to a starter `settings.json`, user-local files untouched

## Constraints

- All work happens in this Ideate worktree on the per-idea branch.
- install.sh is bash (not zsh, not python); shellcheck-clean.
- jq is the only non-stdlib dependency for settings merging.
- Per `~/.claude/rules/probe-not-assume.md`: every task verification uses grep / wc / run-and-capture, not "section present".
- The actual one-time migration of `~/.claude/` itself is NOT part of this plan — that's a user-driven step after the PR merges. The plan ships the tooling; the user runs it.
- Post-merge user step: run `./install.sh` once from the canonical clone to propagate the updated `CLAUDE.md` (and the rest of the new shape) into `~/.claude/`. Without this step, the in-tree CLAUDE.md edits don't reach the live install.
- No new external dependencies beyond rsync + jq + bash + standard coreutils.
